## 0. Role and skill activation

Act as a senior full-stack developer and design lead doing a competitive design audit before touching code. Activate **Frontend/Mobile**, **API/Architecture**, and **Quality/Testing** skills from the `jeffallan/claude-skills` framework. State which skills you're activating before you start.

This is not a "redesign from scratch" — it's a **competitive elevation pass**: audit how direct-selling/MLM sites like Longrich, Norland, and similar Chinese-manufacturer-backed African direct-selling brands typically present themselves, keep the functional patterns that genuinely serve distributors and customers, and deliberately discard the visual habits that make the category look untrustworthy. Songtai Life should read as a premium global wellness brand that happens to have a distributor program — not as "another MLM site."

## 1. What the category typically gets right (keep / adapt these functional patterns)

- Clear, prominent path to "Become a Distributor" / join flow, with entry-level pricing shown transparently up front (Songtai Life already does this — don't bury it)
- A visible compensation/rewards structure that doesn't require downloading a PDF to understand the basics
- Trust signals: certifications, manufacturing credentials, company history/heritage (Songtai Life has real ones — ISO, HACCP, Halal, GMP, 45+ years — lean into these harder than competitors typically do, since ours are genuinely verifiable)
- A sponsor/referral link or code system that's easy for a distributor to share
- Local contact info and payment methods relevant to the market (mobile money, WhatsApp support)

## 2. What the category typically gets wrong (deliberately avoid these — be specific, not vague)

Based on a review of how Longrich, Norland-style, and comparable direct-selling sites in this market commonly present themselves, and general web design failure patterns, avoid:

- **Visual clutter and competing CTAs**: banners, badges, and "Join Now!!!" urgency text all fighting for attention on one screen, with no clear single next action. Songtai Life should have exactly one primary CTA per screen/section.
- **Low-quality or generic stock photography**: stacks of cash, luxury cars, and staged "success lifestyle" images that read as inauthentic. Prefer real product photography, real certification documents/badges, and honest, specific imagery over generic wealth-signaling stock photos.
- **Gaudy, high-saturation color combinations** (bright gold + red + multiple neon accents on one page) that reduce legibility and feel more casino than clinic. Songtai Life already has a disciplined, WCAG-AA-verified light/dark token system (green `#016934` / vermillion `#E7380D` — see the existing theme build) — do not introduce additional accent colors outside that system for "excitement."
- **Compensation plan tables as screenshots/images of spreadsheets or scanned PDFs** instead of real, readable, responsive HTML — this is one of the most common and most damaging patterns in the category. Songtai Life's compensation data should render as actual accessible tables/components, not embedded images.
- **Autoplaying carousels and video/audio** that hijack the page on load. No autoplay of anything with sound; any carousel needs visible pause/manual controls.
- **Aggressive pop-ups and forced overlays** demanding contact info before showing any real content. WhatsApp/contact widgets should be a small, dismissible, corner element — never a blocking modal on page load.
- **Inconsistent typography** — multiple unrelated fonts, ALL-CAPS walls of text, and font sizes that vary randomly by section. Songtai Life already has a defined type scale and a chosen display/body pairing (see the theme build) — enforce it everywhere, including inside admin-generated content like FAQs and blog posts.
- **Testimonial walls of uncredited stock headshots** with generic praise. If testimonials are used at all, they must be attributable (name, region, real or clearly placeholder-marked) — never anonymous stock photography presented as if real.
- **Slow, image-heavy pages with no optimization** — the category is notorious for multi-megabyte hero images and unoptimized product photos. Every image must be served responsively (correct `next/image` usage, modern formats, lazy-loaded below the fold).
- **Buried or absent legal/company information** — company registration, physical address, and clear terms should be easy to find, not hidden three clicks deep. Songtai Life's Douala address and certifications should be visible in the footer sitewide, not just on one page.

## 3. Concrete elevation targets

Rather than "look nicer than Longrich" as a vague goal, hit these specific, checkable bars:

1. **One clear CTA per viewport** on every page — audit the current homepage and product pages for competing CTAs and consolidate.
2. **Compensation plan and product data render as real components** — tables, accordions, interactive PV calculators where useful — never as an image of a table or an embedded PDF viewer as the primary way to view this information. (A downloadable PDF can still exist as a secondary "official document" link, but it's not the primary UI.)
3. **Photography discipline**: audit every image currently in use. Flag and replace any generic "success lifestyle" stock photography with real product shots, real certification badges/documents, or tasteful abstract brand-pattern treatments consistent with the theme's signature gradient element. If no real photography exists yet for a given slot, use a designed placeholder (branded pattern, icon, or color block) rather than a mismatched stock photo — a clean placeholder reads more premium than a generic stock image.
4. **Zero autoplay, zero forced overlays** — audit every page for autoplaying carousels/video and blocking pop-ups; convert to user-initiated interactions.
5. **Typography enforcement** — no ad hoc font sizes or families outside the defined type scale, anywhere, including inside dynamically rendered admin content (FAQs, blog body text, product descriptions).
6. **Performance bar**: Core Web Vitals in the "Good" range (LCP < 2.5s, CLS < 0.1, INP < 200ms) on the homepage and product pages — run Lighthouse before and after and report the delta.
7. **Trust-forward information architecture**: certifications, company heritage, and physical/contact info visible in the footer on every page, not confined to one buried "About" section.
8. **Accessible, real navigation** — a visible, logical menu (not a hidden hamburger-only pattern on desktop), descriptive link labels, and working keyboard navigation throughout — audit against the WCAG AA contrast and focus-visibility work already defined in the theme build.

## 4. Process

1. Take screenshots (or describe in detail if screenshots aren't available in this environment) of the current homepage, products page, and any comp-plan/join page.
2. Score each against the section 2 anti-pattern list and section 3 targets — call out specifically what's currently present that needs to change, don't assume.
3. Propose the fix per item, referencing the existing token/typography system from the theme build (don't introduce new colors or fonts to solve these problems).
4. Implement page by page, starting with the homepage and the distributor join flow (highest-traffic, highest-trust-sensitivity pages), then products, then compensation/FAQ/blog.
5. Re-run Lighthouse and a manual click-through after each page to confirm no regressions.
