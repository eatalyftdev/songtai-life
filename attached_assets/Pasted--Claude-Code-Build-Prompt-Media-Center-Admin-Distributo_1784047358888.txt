## 1. Schema already in place (no migration needed — build against this)

```
media_categories  (id, category_key, name_en/fr, display_order)
  seeded: corporate_videos, anthem_audio, brand_documents,
          marketing_materials, product_media, training_materials

media_assets      (id, category_id -> media_categories,
                    title_en/fr, description_en/fr,
                    file_url, thumbnail_url,
                    file_type ['video'|'audio'|'document'|'image'|'archive'],
                    mime_type, file_size_bytes,
                    visibility ['public'|'distributor_only'],
                    is_published, download_count, display_order,
                    uploaded_by -> profiles, created_at, updated_at)
```

`visibility` is the single switch that drives both surfaces from one table: `public` assets show on the open Media Center page; `distributor_only` assets show only inside the authenticated distributor panel. An asset can be both `is_published = true` and `distributor_only` — that's the normal case for training material.

## 2. Public Media Center page (`/media-center` or `/centre-media`)

- Fetch `media_assets` where `visibility = 'public' AND is_published = true`, grouped by `media_categories` (ordered by `display_order`), each asset ordered by its own `display_order`
- Render per `file_type`:
  - `video`: thumbnail + inline player (or lightbox) for corporate videos, using the same lazy-load discipline as the product video showcase built earlier (no autoplay, no iframe injected until opened)
  - `audio`: an inline audio player for the company anthem/audio assets (native `<audio>` controls or a light custom player — no autoplaying audio on page load, ever)
  - `document`: file-type icon (PDF/DOC/PPT etc. inferred from `mime_type`), title, file size (formatted, e.g. "2.4 MB"), description, direct download button
  - `image`/`archive`: thumbnail preview where applicable, download button
- Every download button increments `download_count` (server-side, not trusted from client) before/on redirecting to the actual file
- Bilingual throughout: category names, titles, descriptions — matching the locale toggle pattern already established sitewide
- Empty state per category if it has no published public assets yet (don't show an empty category header with nothing under it — hide categories with zero visible items)

## 3. Distributor panel — Media & Downloads section

Inside the existing authenticated distributor dashboard (built in the earlier prompt), add a "Media & Resources" or "Marketing Kit" tab:

- Fetch `media_assets` where `is_published = true` AND (`visibility = 'public' OR visibility = 'distributor_only'`) — distributors see everything public users see, plus the distributor-only training/marketing kit
- Same rendering rules as section 2 (players, icons, download tracking)
- Optionally group distributor-only marketing materials (flyers, social media templates, WhatsApp broadcast copy) separately at the top of the tab, since that's what a distributor logging in to promote the business is most likely looking for first — check with product/design intent before assuming ordering, but default to putting `marketing_materials` and `training_materials` categories above `brand_documents`/`corporate_videos` in this specific view
- Make sure this tab respects the same RLS/auth guard as the rest of the distributor dashboard — a logged-out or non-distributor user must not be able to hit an API route directly and pull `distributor_only` assets

## 4. Admin panel — Media Center manager

Add a "Media Center" section to the admin panel (match existing admin routing/auth pattern — admin-role gated via `profiles.role`, same as the hero carousel/gallery/blog admin sections):

- **Upload flow**: file picker → upload to Supabase Storage (create/use an appropriate bucket, e.g. `media-center`, with sensible folder structure like `{category_key}/{uuid}-{filename}`) → on successful upload, create the `media_assets` row with `file_url` (and `mime_type`/`file_size_bytes` read from the uploaded file), `uploaded_by` set to the admin's profile id
- Auto-detect `file_type` from the uploaded mime type (video/*, audio/*, application/pdf and office formats → document, image/* → image, zip/rar → archive) but allow manual override in the form
- Form fields: category (dropdown from `media_categories`), title EN/FR (required), description EN/FR (optional), visibility toggle (public / distributor-only), thumbnail (optional manual upload — auto-generate a thumbnail for video where feasible, otherwise fall back to a category-appropriate icon, matching the pattern already used for product videos)
- Publish/unpublish toggle — unpublishing must immediately remove the asset from both the public Media Center and the distributor panel (query-time gate, not just UI hiding)
- Edit and delete actions; deleting should also remove the underlying Storage object, not just the database row (avoid orphaned files accumulating in Storage)
- Reordering within a category (`display_order`) via drag-and-drop or up/down controls
- A simple "Media Center" overview table showing every asset with category, visibility, published status, download count, and last updated — sortable by download count so Zayne can see which marketing materials distributors actually use

## 5. CDN-backed image delivery, sitewide

Audit every place images are currently served across the site (hero carousel, gallery, product photos, blog images, media center thumbnails, distributor avatars if any) and ensure all of them go through CDN-optimized delivery rather than raw Storage URLs:

- If images are stored in Supabase Storage, use Supabase's built-in image transformation/CDN URLs (resize/format-on-the-fly parameters) rather than serving original-resolution files to every device
- Ensure the Next.js `next/image` component is used everywhere an image renders (not raw `<img>` tags) so Vercel's own image optimization/CDN layer applies on top — check the codebase for any raw `<img>` usage and convert it
- Set appropriate `sizes` attributes on every `next/image` usage so responsive images actually serve the right resolution per viewport, not the largest available
- Serve modern formats (WebP/AVIF) with fallback, and lazy-load every image below the fold (hero images and above-the-fold content should NOT be lazy-loaded — set `priority` appropriately on those)
- Set long-lived cache headers on static image assets (logo, icons, category thumbnails) since they change infrequently
- Verify video/audio files in the Media Center are also served efficiently — large corporate video files should stream, not force a full download before playback starts; confirm Supabase Storage or the chosen host supports range requests for this
