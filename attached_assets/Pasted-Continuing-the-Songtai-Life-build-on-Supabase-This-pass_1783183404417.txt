1. FAQ — SCHEMA + ADMIN CRUD
═══════════════════════════
If FAQ content is currently hardcoded in the FAQ page component, this replaces it with a real Supabase-backed, admin-editable table.

```sql
create table faq_categories (
  id uuid primary key default uuid_generate_v4(),
  name_en text not null,
  name_fr text,
  display_order integer default 0
);

create table faqs (
  id uuid primary key default uuid_generate_v4(),
  category_id uuid references faq_categories(id),
  question_en text not null,
  question_fr text,
  answer_en text not null,
  answer_fr text,
  display_order integer default 0,
  is_published boolean default true,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

alter table faq_categories enable row level security;
alter table faqs enable row level security;

create policy "public_read_faq_categories" on faq_categories for select using (true);
create policy "admin_faq_categories_all" on faq_categories for all using (is_admin()) with check (is_admin());

create policy "public_read_published_faqs" on faqs for select using (is_published = true);
create policy "admin_faqs_all" on faqs for all using (is_admin()) with check (is_admin());
```

**Public FAQ page:** reads `faqs` where `is_published = true`, grouped by `faq_categories`, ordered by `display_order`. Keep the existing searchable-accordion UI (Products/Distributor/Payments/Shipping categorization) — it now just reads from Supabase instead of a hardcoded array. Use the existing `useLocalizedField(row, 'question')` / `useLocalizedField(row, 'answer')` helper so it respects the EN/FR toggle already wired site-wide.

**Admin panel — new `/admin/faq` section:**
- Category management: simple list with add/edit/delete/reorder (drag-to-reorder writing to `display_order`, same pattern as Testimonials/Gallery).
- FAQ list within each category: table showing question (EN, with FR indicator if translated), category, published toggle (inline switch, writes immediately), display order, actions (edit, delete with confirmation).
- Add/Edit form: category select, question_en/question_fr, answer_en/answer_fr (textarea, rich-text not necessary here — FAQ answers are short), is_published toggle.
- Add/delete both work exactly as named: "Add FAQ" opens the create form in a slide-over; delete requires a confirmation modal (this is public content, so accidental deletion should have a clear guard) and, per the existing audit pattern, logs to `audit_logs` via `logAdminAction()`.
- Empty state: "No FAQs yet — add your first question" with the Add FAQ CTA front and center, same convention as every other admin list.
- List subscribes to Supabase Realtime so changes reflect immediately if two admins are editing FAQ content at once.

2. HOMEPAGE FEATURED PRODUCTS — ADMIN-CONTROLLED SELECTION
═══════════════════════════
Currently the homepage's Featured Products section likely just pulls the most recent or all active products. Give admin explicit control over which products show there and in what order.

```sql
alter table products
  add column if not exists is_featured boolean default false,
  add column if not exists featured_order integer default 0;
```

**Public homepage:** Featured Products section now queries `products where is_active = true and is_featured = true order by featured_order`, falling back to showing the most recently added active products if fewer than a minimum threshold (e.g., 4) are marked featured, so the section never looks empty on a fresh site.

**Admin panel — extend the existing `/admin/products` table:**
- Add a "Featured" toggle column (inline switch) to the products table already built.
- Add a dedicated "Homepage Featured" view/tab within Products — shows only `is_featured = true` products, drag-to-reorder (writes `featured_order`), so admin can curate exactly what visitors see first without hunting through the full catalog.
- Live preview note in this tab: a small "View on homepage" link so admin can immediately check how the curated selection looks.

3. PRODUCT CATEGORIES — FULL ADMIN CRUD
═══════════════════════════
`product_categories` already exists as a referenced table (products.category_id) but likely isn't admin-editable yet — fix that.

```sql
alter table product_categories
  add column if not exists name_fr text,
  add column if not exists slug text,
  add column if not exists display_order integer default 0,
  add column if not exists image_url text,
  add column if not exists is_active boolean default true;

-- Backfill slug from existing name if empty (adjust based on actual current column name)
update product_categories set slug = lower(regexp_replace(name, '[^a-zA-Z0-9]+', '-', 'g')) where slug is null;

alter table product_categories enable row level security;
create policy "public_read_active_categories" on product_categories for select using (is_active = true);
create policy "admin_categories_all" on product_categories for all using (is_admin()) with check (is_admin());
```

**Admin panel — new `/admin/products/categories` section** (or a tab within the existing Products page):
- Table: category image thumbnail, name_en/name_fr, slug, product count (computed — how many products reference this category), active toggle, display order, actions (edit, delete).
- Add/Edit form: name_en, name_fr, slug (auto-generated from name_en but editable), category image upload via the existing `MediaUploader`, active toggle.
- **Delete guard:** if a category has products assigned to it, block deletion with a clear message ("This category has N products — reassign or remove them first") rather than silently orphaning products or cascading a delete that wipes catalog data by accident.
- Drag-to-reorder writes `display_order`, which drives both the admin list order and the public-facing category filter pills (Products page and the homepage mega menu category previews) — confirm both consumers read this same order so the whole system stays consistent rather than each screen having its own hardcoded category order.

**Public site updates using this:**
- Products page category filter pills now read live from `product_categories` instead of any hardcoded list.
- Navbar mega menu (Products) category previews pull from the same table + `image_url`.
- Product create/edit form's category dropdown reads from this table too — one source of truth referenced everywhere.

4. GALLERY — CONFIRM/COMPLETE ADMIN EDIT (not just add/delete)
═══════════════════════════
Gallery add/upload and delete were already speced earlier — this closes the gap on **editing** existing entries, since that wasn't explicit before:
- In `/admin/gallery`, clicking an existing image opens an edit form (not just delete) allowing: caption_en/caption_fr update, album reassignment (dropdown of existing albums, or type a new one), display_order change, and swapping the image file itself via `MediaUploader` if needed (replace, not just re-upload alongside).
- Album management: if albums are currently just free-text on each image, add a lightweight `gallery_albums` table (same pattern as `faq_categories`/`product_categories`) so admin manages a clean, consistent list of albums rather than typos creating duplicate near-identical album names:
```sql
create table gallery_albums (
  id uuid primary key default uuid_generate_v4(),
  name_en text not null,
  name_fr text,
  display_order integer default 0
);
alter table gallery_images add column if not exists album_id uuid references gallery_albums(id);

alter table gallery_albums enable row level security;
create policy "public_read_albums" on gallery_albums for select using (true);
create policy "admin_albums_all" on gallery_albums for all using (is_admin()) with check (is_admin());
```
- Public Gallery page's album filter reads from `gallery_albums`, same one-source-of-truth principle as categories/FAQ.
