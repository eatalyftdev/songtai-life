## 3. Design reference — interaction pattern, not source code

For inspiration on making this feel like a premium, interactive carousel rather than a plain static image or a basic fade slideshow, reference the *interaction concept* at `https://horizonx.so/explore/interactive-carousel` — this is a paid, commercially licensed component; **do not copy its source code or attempt to extract/replicate its actual implementation**, since Songtai Life has no license for it. Build an original implementation inspired only by the described interaction pattern:

- Square/tile-shaped preview images arranged in a gentle curved arc, bending around the currently active/selected slide (which displays larger and more prominent than the others)
- Smooth, spring-like motion when transitioning between slides (a duration around 600–700ms feels right, matching the reference's cited timing, but tune to taste — don't chase an exact number)
- A slim progress rail beneath or alongside the carousel indicating position among slides
- Support both automatic advancement and direct interaction: clicking/tapping a tile brings it to the active position; dragging (mouse or touch) can also step through slides
- Subtle depth cues (slight tilt/scale/opacity falloff on the non-active tiles) rather than a flat, static row of thumbnails

Adapt this concept to Songtai Life's actual content and space constraints — the reference is a general-purpose gallery of landscape photos; ours is a product-marketing carousel that also needs to carry a badge label, headline/subtitle copy, and a benefit-icon row per slide (per the `hero_carousel` schema above), so the layout will necessarily differ from the reference — take the *feel* (curved arrangement, active slide prominence, tunable spread/tilt/duration, draggable), not a literal visual clone.

## 4. Required behavior

- **Auto-play every 2 seconds** — the carousel automatically advances to the next active `hero_carousel` slide (where `is_active = true`, ordered by `sort_order`) every 2 seconds, looping back to the first after the last.
- **Pause on interaction**: auto-play pauses when the user is actively dragging/hovering/interacting with the carousel, and resumes after a short idle period — don't fight the user's own input.
- **Respect `prefers-reduced-motion`**: if set, disable auto-play and the spring/curve motion, falling back to a simple, instant slide change on manual interaction only.
- Per slide, render: the image, `badge_label_en/fr` as a small pill (localized), `title_en/fr`/`subtitle_en/fr` if the layout has room (matching the reference screenshot's copy density — keep it tight, this is a compact hero panel, not a full-width hero), the `benefits` array as small icon+label chips, and if `linked_product_id` is set, make the slide clickable through to that product's detail page.
- Preserve the floating "Ask AI" and WhatsApp action buttons as an overlay on top of the carousel, positioned consistently regardless of which slide is active — they are not part of any individual slide's content, they're a persistent UI layer above it.
- Sizing: match the aspect ratio and footprint of the current static image panel in the hero exactly (per the screenshot) — this is a redesign of what fills that space, not a resize of the hero section itself.
- Fully responsive — confirm this collapses sensibly on mobile (likely a simpler single-image auto-advancing slideshow with dot indicators is the right mobile fallback, since the full curved-tile interaction needs horizontal room the mobile hero doesn't have; use judgment, but don't force the full desktop interaction pattern into a cramped mobile viewport).
- Bilingual: badge, title, subtitle, and benefit labels all switch correctly with the site's EN/FR toggle.
- Performance: images lazy-load appropriately except the currently active/first slide (which should be `priority`-loaded like any other above-the-fold hero content, per the CDN/image work already done), and the whole component must not regress the homepage's Core Web Vitals — check Lighthouse before/after.
