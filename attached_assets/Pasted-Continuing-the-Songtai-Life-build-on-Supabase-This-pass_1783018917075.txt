1. SITE SETTINGS TABLE — SINGLE SOURCE OF TRUTH FOR SITE-WIDE CONFIG
═══════════════════════════
Almost everything below (WhatsApp number, GTM ID, social links) needs one place to live and one place to be edited. Create a singleton settings table rather than scattering config across env vars or hardcoded values:

```sql
create table site_settings (
  id uuid primary key default uuid_generate_v4(),
  key text unique not null,
  value jsonb not null,
  updated_at timestamptz default now(),
  updated_by uuid references profiles(id)
);

alter table site_settings enable row level security;

create policy "public_settings_read" on site_settings
  for select using (true);

create policy "admin_settings_write" on site_settings
  for all using (is_admin()) with check (is_admin());

-- Seed default rows
insert into site_settings (key, value) values
  ('whatsapp', '{"number": "", "default_message": "Hi Songtai Life, I would like to know more!", "enabled": false}'),
  ('analytics', '{"gtm_id": "", "ga4_id": "", "enabled": false}'),
  ('socials', '{"facebook": "", "instagram": "", "tiktok": "", "whatsapp": "", "youtube": "", "linkedin": ""}'),
  ('seo_defaults', '{"site_title": "Songtai Life", "meta_description": "", "og_image_url": ""}')
on conflict (key) do nothing;
```

Build a `useSiteSettings()` hook that fetches all rows once, subscribes via Supabase Realtime to `site_settings` changes, and exposes typed values (`whatsapp`, `analytics`, `socials`, `seoDefaults`) globally — every component below (WhatsApp button, GTM script, social section, SEO defaults) reads from this hook, never from hardcoded constants. This is what makes the admin panel changes reflect on the live site without a redeploy.

2. WHATSAPP FLOATING BUTTON
═══════════════════════════
- `<WhatsAppWidget />` — fixed-position floating button (bottom-right, above mobile safe area), rendered globally in the root layout.
- Reads `number` and `default_message` from `useSiteSettings().whatsapp`; renders nothing if `enabled` is false or `number` is empty (don't show a broken button pointing nowhere).
- Click opens `https://wa.me/{number}?text={encodeURIComponent(default_message)}` in a new tab.
- Subtle entrance animation (scale + fade in after page load, ~600ms delay), gentle pulse/glow micro-interaction to draw the eye without being obnoxious, respects `prefers-reduced-motion`.
- Admin control: `/admin/settings` → WhatsApp section — form fields for phone number (with format validation, E.164-ish, e.g. `+237...`), default message text, and an enable/disable toggle. Saves via `supabase.from('site_settings').update(...).eq('key', 'whatsapp')`. Show a live preview of the button in the admin form so whoever's editing sees exactly what visitors will see.

8. APPOINTMENT BOOKING
═══════════════════════════
```sql
create table appointment_types (
  id uuid primary key default uuid_generate_v4(),
  name_en text not null,
  name_fr text,
  duration_minutes integer default 30,
  description_en text,
  description_fr text,
  is_active boolean default true
);

create table appointments (
  id uuid primary key default uuid_generate_v4(),
  appointment_type_id uuid references appointment_types(id),
  name text not null,
  email text not null,
  phone text,
  preferred_date date not null,
  preferred_time time not null,
  message text,
  status text default 'requested' check (status in ('requested','confirmed','completed','cancelled')),
  created_at timestamptz default now()
);

alter table appointment_types enable row level security;
alter table appointments enable row level security;

create policy "public_read_appointment_types" on appointment_types
  for select using (is_active = true);
create policy "admin_appointment_types_all" on appointment_types
  for all using (is_admin()) with check (is_admin());

create policy "public_insert_appointments" on appointments
  for insert with check (true);
create policy "admin_appointments_all" on appointments
  for all using (is_admin()) with check (is_admin());
```
- New public page/section: **"Book an Appointment"** — appointment type selector (e.g., "Product Consultation," "Distributor Onboarding Session," "General Inquiry" — admin-managed via `appointment_types`), date/time picker (block out past dates; optionally cross-check against a simple admin-set weekly availability window rather than allowing literally any time), contact details form, optional message field. Apply the existing rate-limiting pattern (`check_rate_limit('appointment', email, 3, 3600)`) to prevent spam bookings.
- Confirmation state on submit (animated success, matching the established easing/motion language) — actual email/WhatsApp confirmation notifications are a reasonable next-phase addition (via an Edge Function) if you want automated confirmations rather than manual admin follow-up.
- `/admin/appointments` — list view (filterable by status/date), status update action (requested → confirmed/cancelled/completed), synced via Realtime so a new booking shows up immediately for whoever's monitoring the admin panel.
- Add this as a proper nav item and a homepage section/CTA ("Book a Free Consultation") — this is what pushes the site from "storefront" to "agency site," so it deserves real visual presence, not a buried footer link.
