Continuing the Songtai Life build on Supabase. Right now several admin forms likely accept a raw image URL text field (paste-a-link) instead of a real file upload — this pass audits every image/media input across the admin panel and converts it to an actual upload into Supabase Storage via the shared `<MediaUploader />` component, so every asset the site displays is one you actually host and control, not a link to someone else's server that can change, disappear, or get rate-limited without warning.

═══════════════════════════
1. WHY THIS MATTERS (context for the build, not just a preference)
═══════════════════════════
A URL-based image field means: the image can vanish if the external host takes it down, it can be swapped by whoever controls that URL (a real security/trust risk on a public-facing brand site), it's not covered by your own CDN/caching, and you have zero control over its dimensions/format/optimization. Every image on Songtai Life should live in Supabase Storage (`media`, `documents`, or `testimonials` buckets already established) so it's yours: backed up with the rest of your data, served consistently, and immune to a third party breaking your site.

═══════════════════════════
2. AUDIT — FIND EVERY URL-TEXT-INPUT FOR MEDIA
═══════════════════════════
Search the admin panel codebase for any form field currently labeled/typed as a URL string for an image, video, or document, rather than a file upload. Based on the schema built so far, this almost certainly includes:
- Products: `images[]` (if currently a comma-separated URL list or repeatable URL text inputs)
- Blog posts: featured image field
- Hero carousel / `hero_carousel` (or `gallery_images` reused for this) entries
- Gallery images: `url` column, if currently populated by pasting a link rather than uploading
- Testimonials: `video_url` (this one may legitimately stay a URL if pointing to an external host like YouTube — see Section 5 exception)
- Product categories: `image_url`
- Gallery albums: any cover image
- Site Settings → Branding: `logo_url`, `logo_dark_mode_url`, `favicon_url`
- Site Settings → SEO Defaults: `og_image_url`
- Media Center documents (catalogues/brochures) if currently linked rather than uploaded

Every one of these gets converted per Section 3 below.

═══════════════════════════
3. STANDARDIZE ON THE SHARED MediaUploader COMPONENT
═══════════════════════════
If `<MediaUploader />` already exists (speced in an earlier pass — drag-and-drop, progress bar, preview, file-type/size validation, uploads to a Storage bucket and returns the public URL), confirm it's the *only* image input mechanism used anywhere in the admin panel. If any form still has a plain `<input type="text" placeholder="Image URL">`, replace it with this component.

`<MediaUploader />` behavior to confirm/enforce:
- Accepts drag-and-drop or click-to-browse, restricted to actual image MIME types (`image/jpeg`, `image/png`, `image/webp`, `image/avif` — reject anything else client-side before it even attempts upload).
- Shows a live preview thumbnail immediately (from the local file, before upload completes) so the admin sees what they picked, then swaps to the real uploaded image once the Storage call resolves.
- Enforces a sane max file size (e.g., 5MB for product/blog images, 10MB for hero/carousel assets) with a clear error message, not a silent failure or a stuck progress bar.
- On successful upload, writes the returned Supabase Storage public URL into the parent form's state — the admin never sees or types a URL manually; it's populated automatically.
- Supports **replace** (upload a new file into the same field, old file optionally deleted from Storage or left orphaned with a cleanup job later — decide based on whether you want image history/rollback) as well as **remove** (clear the field entirely).
- For fields that need multiple images (Products, Gallery bulk upload), support multi-file selection/drag in one action, uploading each to Storage and appending to the array field, with per-file progress and the ability to reorder or remove individual images before saving.
