2. OUTBOUND PAYMENT — COLLECT (customer pays)
═══════════════════════════
Edge Function `initiate-payment`:
```ts
import { PaymentOperation } from '@hachther/mesomb';

const client = new PaymentOperation({
  applicationKey: Deno.env.get('MESOMB_APPLICATION_KEY')!,
  accessKey: Deno.env.get('MESOMB_ACCESS_KEY')!,
  secretKey: Deno.env.get('MESOMB_SECRET_KEY')!,
});

// Inside the handler, after creating the `orders` row and a `payments` row
// with a locally-generated unique idempotency_key / trxID:
const response = await client.makeCollect({
  nonce: crypto.randomUUID(),           // required — prevents replay attacks, must be unique per request
  payer: payerPhoneNumber,              // local format, e.g. '670000000' — no country code prefix
  amount: order.total_xaf,
  service: paymentMethod,               // 'MTN' or 'ORANGE'
  country: 'CM',
  currency: 'XAF',
  trxID: payment.id,                    // your own payments.id — used for reconciliation against MeSomb's records
  reference: `ORDER-${order.id}`,
  customer: {
    email: order.customer_email,
    firstName: order.customer_first_name,
    lastName: order.customer_last_name,
    town: order.customer_town ?? 'Bamenda',
    region: order.customer_region ?? 'Northwest',
    country: 'CM',
  },
  location: { town: 'Bamenda', region: 'Northwest', country: 'CM' },
  products: order.items.map((item) => ({
    name: item.product_name,
    category: item.category_name,
    quantity: item.quantity,
    amount: item.unit_price_xaf,
  })),
});

if (response.isOperationSuccess() && response.isTransactionSuccess()) {
  // Update payments.status = 'success', orders.status = 'paid' — but see Section 4:
  // prefer letting the WEBHOOK be the source of truth for final status, since MTN/Orange
  // MoMo collections are a customer-approval flow (the customer must confirm on their phone) —
  // the synchronous response here confirms the REQUEST was accepted, not necessarily that
  // the customer has approved payment yet. Set orders.status = 'pending_confirmation' here,
  // and let the webhook (Section 5) move it to 'paid' once MeSomb confirms actual completion.
} else {
  // Update payments.status = 'failed', surface response.message to the user
}
```
Important nuance not to miss: `makeCollect` with `mode: 'synchronous'` (the default) waits for the mobile money prompt to be answered before responding, so in practice the response often does reflect final status for MTN/Orange in Cameroon — but still treat the webhook as authoritative for updating `orders.status`, since network timeouts on the synchronous call are exactly the scenario where the webhook is the only reliable signal you'll get.

4. TRANSACTION STATUS RECONCILIATION (for stuck/ambiguous transactions)
═══════════════════════════
For any payment/withdrawal that's been `pending`/`processing` longer than a reasonable window (e.g., 5 minutes), use `checkTransactions` to actively query MeSomb rather than waiting indefinitely on a webhook that may have failed to deliver:
```ts
const results = await client.checkTransactions([payment.mesomb_transaction_id], { source: 'MESOMB' });
// results[0].status is one of: SUCCESS | FAILED | PENDING | REFUNDED — update your local record accordingly
```
Build a scheduled reconciliation job (Supabase cron via `pg_cron` or a scheduled Edge Function invocation) that runs this check on any payment/withdrawal stuck in a non-final state for too long — this is the safety net for the "webhook never arrived" case, which does happen in real deployments (network issues, your endpoint being briefly down during a deploy, etc.).

5. WEBHOOK ENDPOINT — CORRECT SIGNATURE VERIFICATION (this replaces any earlier HMAC assumption)
═══════════════════════════
MeSomb's real webhook signature scheme, confirmed from their current docs:

- Headers sent with every webhook delivery:
  - `X-MeSomb-Webhook-Event-Id` — unique event ID, use for deduplication
  - `X-MeSomb-Webhook-Request-Timestamp` — unix timestamp
  - `X-MeSomb-Webhook-Signature` — format `t=<timestamp>,v1=<hex hmac-sha256>`
- Signed payload to verify against = `"<timestamp>.<raw_request_body>"` (timestamp, a literal dot, then the **raw, unparsed** request body — not a re-serialized JSON object, since any whitespace/field-order difference breaks the signature).
- Signature = `HMAC-SHA256(webhook_signing_secret, signed_payload)`, hex-encoded, compared using a timing-safe comparison.
- Reject if the timestamp is more than 5 minutes old (replay protection).

Edge Function `mesomb-webhook`:
```ts
import { createHmac, timingSafeEqual } from 'node:crypto'; // or Deno's std/crypto equivalent

Deno.serve(async (req) => {
  const rawBody = await req.text(); // MUST read as raw text before any JSON.parse — this is critical
  const signatureHeader = req.headers.get('x-mesomb-webhook-signature');
  const eventId = req.headers.get('x-mesomb-webhook-event-id');

  if (!signatureHeader || !eventId) {
    return new Response('Missing signature headers', { status: 400 });
  }

  const parts = signatureHeader.split(',');
  const timestampPart = parts.find((p) => p.startsWith('t='));
  const signaturePart = parts.find((p) => p.startsWith('v1='));
  if (!timestampPart || !signaturePart) {
    return new Response('Invalid signature format', { status: 400 });
  }

  const timestamp = timestampPart.slice(2);
  const receivedSignature = signaturePart.slice(3);

  const now = Math.floor(Date.now() / 1000);
  if (Math.abs(now - Number(timestamp)) > 300) {
    return new Response('Timestamp outside tolerance', { status: 400 });
  }

  const signedPayload = `${timestamp}.${rawBody}`;
  const expectedSignature = createHmac('sha256', Deno.env.get('MESOMB_WEBHOOK_SECRET')!)
    .update(signedPayload, 'utf8')
    .digest('hex');

  const receivedBuf = Buffer.from(receivedSignature, 'hex');
  const expectedBuf = Buffer.from(expectedSignature, 'hex');
  if (receivedBuf.length !== expectedBuf.length || !timingSafeEqual(receivedBuf, expectedBuf)) {
    return new Response('Invalid signature', { status: 400 });
  }

  // ── DEDUPLICATION — check BEFORE processing, per Section 6 table ──
  const { data: existing } = await supabaseAdmin
    .from('mesomb_webhook_events')
    .select('id')
    .eq('event_id', eventId)
    .maybeSingle();

  if (existing) {
    // Already processed — MeSomb may redeliver on network issues or manual replay.
    // Return 200 WITHOUT reprocessing, per their explicit deduplication guidance.
    return new Response(JSON.stringify({ received: true, duplicate: true }), { status: 200 });
  }

  const event = JSON.parse(rawBody); // safe to parse now that signature is verified
  await supabaseAdmin.from('mesomb_webhook_events').insert({ event_id: eventId, event_type: event.event_type, payload: event });

  // ── ROUTE BY EVENT TYPE ──
  switch (event.event_type) {
    case 'payment.transaction.success': {
      const txn = event.data.object;
      await supabaseAdmin.from('payments').update({ status: 'success', mesomb_transaction_id: txn.pk })
        .eq('idempotency_key', txn.reference);
      await supabaseAdmin.from('orders').update({ status: 'paid' })
        .eq('id', txn.reference.replace('ORDER-', ''));
      // Trigger commission calculation here (call the existing calculateCommission logic)
      break;
    }
    case 'payment.transaction.failed': {
      const txn = event.data.object;
      await supabaseAdmin.from('payments').update({ status: 'failed' }).eq('idempotency_key', txn.reference);
      await supabaseAdmin.from('orders').update({ status: 'cancelled' })
        .eq('id', txn.reference.replace('ORDER-', ''));
      break;
    }
    // Add cases for checkout.session.* and securepay.* events only if those MeSomb
    // products (Checkout Sessions / Secure Payments) are actually in use — the standard
    // Collect/Deposit flow above only needs the payment.transaction.* events.
    default:
      console.log(`Unhandled MeSomb event type: ${event.event_type}`);
  }

  // ── ALWAYS RETURN 200 ON SUCCESSFUL PROCESSING ──
  // This is the actual fix for "not giving 200 OK": the response must be sent AFTER
  // verification and processing succeed, with no unhandled exception in between.
  // Wrap the event-type switch in try/catch so a bug in one event handler doesn't
  // prevent the 200 response — log the error, still return 200 if the signature/dedup
  // checks passed, since a 200 tells MeSomb "received", not "business logic succeeded".
  return new Response(JSON.stringify({ received: true }), { status: 200 });
});
```

6. DEDUPLICATION TABLE
═══════════════════════════
```sql
create table mesomb_webhook_events (
  id uuid primary key default uuid_generate_v4(),
  event_id text unique not null,
  event_type text not null,
  payload jsonb not null,
  received_at timestamptz default now()
);

alter table mesomb_webhook_events enable row level security;
create policy "admin_read_webhook_events" on mesomb_webhook_events for select using (is_admin());
-- No insert/update/delete policy for regular roles — only the Edge Function (using the service role key) writes here.
```
Also add a `mesomb_transaction_id` column to `payments` if not already present, to store MeSomb's `pk` (transaction UUID) for use with `getTransactions`/`checkTransactions` reconciliation.
