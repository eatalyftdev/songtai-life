## 2. Design token plan (build this exactly, then critique it against the brief before coding)

### Color system

| Token | Light mode | Dark mode | Use |
|---|---|---|---|
| `--color-bg` | `#FCFBF8` (warm porcelain white, faint warmth — not stark `#FFF`, not the generic AI cream `#F4F1EA`) | `#0B1410` (near-black with a green undertone, drawn from Songtai Green darkened — not neutral gray-black) | Page background |
| `--color-surface` | `#FFFFFF` | `#111C16` | Cards, panels |
| `--color-fg` | `#141A17` (near-black, green-tinted ink) | `#F2F5F3` (soft warm white, not pure `#FFF` — reduces eye strain) | Primary text |
| `--color-muted` | `#5B655F` | `#9CA9A2` | Secondary text, captions |
| `--color-border` | `#E4E2DB` | `#22322A` | Dividers, input borders |
| `--color-primary` | `#016934` | `#1E9A56` (lightened for AA contrast on dark bg) | Primary buttons, links, active states |
| `--color-primary-fg` | `#FFFFFF` | `#06120D` | Text/icons on primary-filled elements |
| `--color-accent` | `#E7380D` | `#FF6B3D` (lightened for AA contrast on dark bg) | Secondary CTAs, highlights, badges, the signature ribbon (see below) |
| `--color-accent-fg` | `#FFFFFF` | `#1A0400` | Text/icons on accent-filled elements |
| `--color-gold` | `#B8862E` | `#D9A94B` | Reserved strictly for certification badges / VIP-tier markers — do not use for anything else, it stays rare and premium |

Every pairing above must be verified to meet **WCAG AA** (4.5:1 for body text, 3:1 for large text/UI components) in both modes before you consider the token system final. Run an actual contrast check (e.g. a small script or an accessibility linter) rather than eyeballing it — the raw logo green (`#016934`) and vermillion (`#E7380D`) both pass AA on white but the dark-mode variants are deliberately lightened because the raw hexes fail AA against `#0B1410`; do not "fix" this by darkening the background back toward pure black, which would break the brand-tinted dark surface.

### Typography

Pick two typefaces deliberately, not defaults:
- **Display face**: something with quiet gravitas that nods to heritage without going full serif-pharmacopoeia-cliché — e.g. a warm, slightly humanist serif or a confident semi-serif (evaluate options like Fraunces, Source Serif 4, or Newsreader at a heavier weight; pick one and justify it in a code comment). Used for H1/H2 and the hero only — restraint elsewhere.
- **Body/UI face**: a clean humanist sans with excellent multilingual (French accent) support — e.g. Inter, General Sans, or Public Sans. Used everywhere else, including French copy — verify accented characters (é, è, à, ô, ç, œ) render correctly in both faces at all weights used.
- Define a type scale (e.g. 12/14/16/18/24/32/48/64px or a modular scale) as CSS custom properties, not ad hoc sizes scattered through components.

### Signature element

The logo's "S" mark is a single ribbon-like form that transitions from vermillion to green. Build **one** recurring signature motif from this: a thin diagonal gradient rule (vermillion → green, following the logo's actual gradient angle, not a generic left-to-right) used sparingly as a section divider or underline accent — for example beneath the site header, or as an accent stroke on the hero. Do not scatter it everywhere; it should read as intentional, not decorative filler. No other element should try to be "the signature" — pick this one and execute it with precision (exact gradient stops sampled from the logo, not eyeballed).

## 3. Implementation requirements

- Implement as CSS custom properties (`:root` for light, `[data-theme="dark"]` or `.dark` for dark — match whatever theme-switching convention already exists in the repo; if none exists, use `prefers-color-scheme` as the default with a manual override toggle stored in local state/cookie, not `localStorage`/`sessionStorage` if this ever needs to run inside a Claude artifact context — for the main Next.js site itself, normal browser storage/cookies are fine)
- Every existing component (buttons, nav, cards, forms, badges, footer, admin panel) must be re-themed to pull from these tokens — no hardcoded hex values left in component files. Grep the codebase for hardcoded colors (`#`, `rgb(`, common Tailwind color classes like `bg-orange-500`) and replace with token-driven classes/variables.
- Buttons: primary CTA uses `--color-primary`, secondary/alternate CTA uses `--color-accent` — don't use both on the same view for competing actions, that dilutes hierarchy.
- Focus states: visible keyboard focus ring on every interactive element, in both modes, using a color that meets 3:1 contrast against its background (don't rely on the browser default, which often disappears on dark backgrounds).
- Reduced motion: respect `prefers-reduced-motion` for any transitions tied to the theme toggle or the signature gradient element.
- Theme toggle control: accessible (labelled, keyboard-operable), placed in the header/nav, persists the user's choice.
